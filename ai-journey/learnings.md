# Credit Engine - Learnings
> What worked, what didn't, what you'd do differently

## What worked well

- **SDD - Spec-Driven Development** has proven to be a consistent approach to developing and documenting software in a reliable and maintainable manner;
- **SDD** addresses a longstanding documentation problem, since the quality of the output explicitly depends on a good specification. This certainly helps with software maintenance and evolution;
- **Codex** read the requirements specification, identified gaps, and I moved to the next stages only when the preceding specification document was complete and clear;
- **Codex** genuinely helps with refinement. It drew my attention to requirement details and gaps on several occasions, for example when validating states and regions and validating rules on application starting up.

## What didn't work

- Not writing the requirements specification in sufficient detail requires more time to refine it before generating code. However, I believe this is a realistic scenario in which an agent can help identify gaps in the requirements, including by making rules explicit.

## What I'd do differently

- I would have explored GitHub Spec Kit more thoroughly.
